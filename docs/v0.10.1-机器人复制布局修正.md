# v0.10.1 · 机器人复制布局修正

账号与线路、初始密码、商店登录码和订单卡码保留原来的复制按钮、顺序与其他操作。移除 v0.10.0 追加的“第三方客户端复制帮助”“兼容复制 · N”“兼容复制卡码”。原有业务流程、Mini App 复制及管理员核款保持原样。

## 复制方式

原有复制按钮继续使用 Telegram `copy_text`，由支持此功能的客户端直接写入剪贴板。对应的完整内容同时作为原消息中的 `code` 文本实体显示，可由支持等宽文本复制的客户端点按或长按复制。没有新增帮助按钮、辅助复制按钮或独立复制消息。

文本实体使用 UTF-16 偏移，兼容中文、非 BMP 字符（例如 emoji）和包含尖括号、反引号、`&` 的密码。图片说明在截断和平衡高度之后重新计算 `caption_entities`，避免复制错位或 Telegram 拒绝整个面板。复制正文、按钮和等宽内容来自同一份值；不把密码或商店登录码放进回调参数、额外的网页链接或日志。

Telegram Bot API 规定每个按钮只能选择一种动作。`copy_text` 是客户端动作，不能与 `callback_data` 同时设置，Bot 也拿不到点击复制按钮时的客户端类型，因此不存在服务端自动为 Telegram X 等未实现此动作的客户端切换剪贴板接口的通用办法。不能宣称所有第三方客户端都已实现原按钮的一键复制；不支持时需使用原文的点按/长按复制。依据：[InlineKeyboardButton](https://core.telegram.org/bots/api#inlinekeyboardbutton)、[CopyTextButton](https://core.telegram.org/bots/api#copytextbutton)。

## 旧面板

升级后，`/start`、`/panel` 或现有面板中的正常操作会使用恢复后的布局。历史消息不会批量修改；点到历史辅助复制按钮时，仅在本人私聊刷新为当前主面板，不再从旧消息取出密码或卡码。普通用户、管理员、白名单共用同一套输出规则，现有权限检查不变。

## 验证范围

- 精确复制值：账号、线路、密码、登录码；中文、emoji、特殊字符、重复值、重叠内容及 UTF-16 范围。
- 文字和横图面板：保留原消息 ID，保留原按钮数量、顺序与动作，检查截断后实体范围。
- 旧面板：本人私聊安全刷新，群组拒绝，禁止从旧消息回显敏感值。
- GitHub 正式发布流程执行 PostgreSQL 回归及安装、升级、回滚、卸载检查；发布后再核对目标服务器版本和健康状态。

Telegram X 等实体设备的剪贴板操作需要相应客户端实测，服务端测试不能代替。自动下载追新系统仍按约定后建。
