# v0.11 · 可信观影摘要与签到显示

## 用户可见内容

- Bot → 我的账户：最近30天有效观影时长、最后有效观影时间。
- Mini App → 我的：同源的观影摘要、采集状态、统计说明及最后服务器采样时间。
- Mini App → 签到与保号：今日签到/已签到按钮旁显示钱包剩余可用积分和积分名称。使用钱包 `available` 投影，冻结积分不计入；签到成功后刷新同一账户数据。
- Bot 主、次面板的最小预留高度各减少约两行，功能和按钮顺序保持不变。账户新增字段仍保留在图片说明的长度范围内。

## 时间与统计口径

这里的“最近30天”是截至请求时间的滚动30天（30×24小时），与保号结算使用的权益窗口分别展示，避免管理员/永久白名单没有到期日时出现无效窗口。保号 A/B 的门槛、选择和结算规则不变。

数据仅来自后端用既有 Emby 凭据读取的真实 `/Sessions` 会话：电影或剧集正在播放，连续采样间隔不超过90秒，进度变化符合原有校验范围，才产生已确认区间。一个有效区间的秒数不超过墙钟间隔和进度增量中的较小值。暂停、跳进度、报告缺失、首次未确认采样不会增加时长。所有设备的区间取并集，同一秒不重复累计。

最后观影时间取最后一段已确认区间的结束时间，不使用账号登录、Emby 设备活动、任务运行、全局采样时间，也不把影片总时长当成已观看时长。双方统一使用 Unix 秒传输、北京时间显示。

没有可信区间时显示“暂无有效记录”，没有最后观影证据时显示“暂无记录”；采集关闭、等待或过期明确提示只显示已有确认记录，不能将缺报或未采集的时间推算成实际已观看。

## 持久化与兼容

沿用 PostgreSQL `twilight_state` 的 JSON 状态，新增 `retention.viewing_watches`（保留37天的已确认展示区间）及 `retention.last_watch_at`（每用户最后有效观影时间）；不新增数据库表或修改既有字段。观影展示区间独立于可能被保号救济结算消费的资格区间，保证已确认历史不随结算消失。

旧版本已有的 `retention.watches` 是可信区间，可作为历史回填；仅复制实际存在的数据，不生成未采集时期的观影。升级前已被裁剪/消费且无现存记录的历史无法凭空恢复。最后时间只有现存证据时才回填，绝不填当前时间。

新字段随既有快照、完整备份和迁移导入/导出保存。备份验证检查用户归属与区间边界；导入仍清空实时采样游标、保留历史事实，等待下一次服务器采样。删除用户同时删除其观影区间、最后时间及会话样本，防止 UID 复用继承他人历史。

Mini App `account` 返回新增的 `viewing` 字段：`available`、`window_start`、`window_end`、`seconds`、`has_window_records`、`last_watched_at`、`last_poll`、`quality`、`source`。只查询当前认证用户，不接受请求中的目标 UID；没有新建匿名观影接口。

## 验证范围

回归覆盖30天边界裁剪、多设备并集、无记录、未来/非法区间、首次采样、缓冲、暂停、跳进度、长断报、保号结算隔离、最后时间超过37天仍保留、快照验证、Bot 与 Mini App 一致、UTF-16 图片说明长度及可用积分显示。前端覆盖秒数格式、不使用当前时间补值、北京时间跨日和三语文案一致性。

没有真实影片或完整观影回传时，生产验收仅能确认现存真实数据和空状态，不能用测试库的模拟记录冒充用户观影，也不能宣称已经完成真实影片的长时播放实测。
