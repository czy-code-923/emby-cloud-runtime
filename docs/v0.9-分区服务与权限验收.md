# v0.9 · 分区服务与权限验收

## 当前实例的扩展入口

后台“服务集成 → 分区服务与权益”预留三项：见微音乐、见微有声小说、见微白名单影视。它们共用当前Emby实例和同一播放账号，以媒体库ID区分权限；没有另装Emby，也没有移动已有电影或剧集。初始全部关闭，不选中已有媒体库、不生成虚构域名、不修改现有用户权益。

启用时选择真实媒体库、填独立HTTPS域名（可暂空）、设置注册/续期卡入口、积分价格和卡券天数。独立域名保存后在“站点与入口”使用现有Cloudflare DNS证书流程申请、续期并发布。普通/白名单原有播放域名不可复用为独立分区域名，避免配置歧义。

这是同一Emby实例的库权限分区。若以后部署不同Emby实例、独立账号数据库或纯文本小说阅读器，仍需对应后端适配，不能仅填写名称就变成已部署服务。有声小说入口可对接当前实例内对应媒体库；没有内容或未启用时，不向用户展示未开通的线路。

## 权限与卡券

| 身份/权益 | 普通影视库 | 扩展分区库/独立线路 |
|---|---|---|
| 管理员播放账号 | 按现有管理员规则 | 已启用分区可用，不授予原生管理权 |
| 有效白名单 | 普通和白名单线路 | 已启用分区可用，无需另兑卡 |
| 普通影视会员 | 按影视有效期 | 默认拒绝；对应分区权益可用 |
| 分区注册码/续期码 | 不增加影视时长或改变身份 | 仅增加对应服务天数，保留剩余时间 |
| 白名单到期 | 剩余影视时长仍可用 | 失去身份附带权限，自己的分区卡权益仍按期限生效 |

分区卡需要已有统一Emby账号。注册码用于首次开通或已到期服务，续期码用于已有服务记录；两种开关控制新码生成，不撤销已发出的合法单次码。卡码列表保留服务备注。群内 `redeem_` 深链与Bot/Mini使用同一核销路径，不把服务注册码误判为重复创建主Emby账号。服务卡不占主账号注册名额。

权限既验证域名，也同步Emby `EnabledFolders`。配置为专属分区的媒体库会从普通影视权限中移除；普通用户不能用主线路绕过专属线路。停止服务、到期、身份变更均在网关重新核验，缓存的登录令牌不缓存角色权限。原生owner保留私有管理；托管播放账号保持非原生管理员。

影视到期但分区权益仍有效时，不整体关停账号：普通影视线路拒绝访问，保留获权分区。分区也到期才按原有停用流程处理。手动禁用、换绑中账户不会被分区权益自动解除限制。

## 积分商店

原月/季/年影视卡保持。可按分区开启一个可编辑天数/积分价格的权益商品；Bot按钮、确认价格、本人专属发码、Mini商品与兑换操作复用同一数据库事务。不可用商品禁用按钮，管理员/有效白名单已有分区权益，不重复扣分购买。冻结积分不能消费；重复请求只扣一次，重复核销拒绝。

发码本身不改变A/B选择或影视截止日。普通影视卡核销后按v0.8规则处理；服务卡核销只改变对应分区。服务权益来源与影视权益来源分开，退款撤回只影响该来源剩余部分，保留后来独立续期。系统仍不执行支付平台转账。

## 机器人补修

可选横图使用独立短超时，父操作30秒预算不再覆盖图片自己的8秒预算。内置横图随后端打包，直接上传Telegram并复用file_id，避免Telegram回源Cloudflare失败；图片失败仍保留文字按钮。自定义广告配置不覆盖。`/services`和“更多服务”可查看已开放分区；未获权普通用户看不到线路。Mini首页按需展示分区卡片。

## 验收方法

- 独立PostgreSQL：普通/白名单/管理员库权限、白名单到期、服务卡注册续期、积分幂等扣费、保号互不影响、来源退款与备份、注册码不占主名额。
- 模拟Emby：检查实际发送的库白名单、原生管理权保持false、服务域名拒绝未获权角色。
- 生产：`twilight audit-whitelist --confirm AUDIT_WHITELIST`创建随机命名的临时原生播放账户及平台白名单身份，通过真实HTTPS验证普通/白名单线路200；让该临时身份白名单到期后验证专属线路403、普通线路200。只清理本次创建且ID/名称仍匹配的临时账号，绝不更改现有用户、订单或积分。验证失败必须记录失败，不能把模拟测试当生产通过。
- 完整发布继续运行安装、保留数据升级、回滚、卸载和重装；真实第二台VPS实装、长期观看及跨到期观察另外记录。

自动下载追新按用户要求后建，现有求片队列、审核、海报、事件回调与入库核验接口保留。
