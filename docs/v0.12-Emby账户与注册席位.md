# v0.12 · Emby 账户与注册席位

## 显示范围

Bot“我的账户”只展示 Emby 账号、当前状态、账户类别、可用积分、有效期、安全码提醒和真实观影摘要。使用“· 图标 字段 | 内容”，不再展示 Web 用户名、重复用户名或 Telegram ID，不使用 Web 用户名作为 Emby 名称的回退。服务状态、积分商店、保号信息使用同类图标提示，原按钮和同消息更新保留。

注册席位汇总只提供给尚未绑定 Emby 的已认证会员，包括已取得资格但尚未创建 Emby 的待开通会员。Bot 首页、服务状态和 Mini App 首页遵循同一条件。已有 Emby 绑定的普通用户、管理员、白名单，以及过期或停用的绑定账号，均不显示席位汇总；Mini App `account` 和 `service` 接口也省略 `registration`，并非仅在网页上隐藏。原有鉴权和会员功能保持不变。

Mini App 新增独立玻璃样式席位卡，总数、已注册和剩余采用三列排列，预留名额单独说明。已开通时整张卡隐藏；无席位字段的旧接口仍可正常显示其它内容。未开通的头部不回退显示 Web 用户名。

## 统计口径

- 总注册席位使用后台 `SAR.emby_user_limit`，不是 `SAR.user_limit` 的 Web 用户上限；配置小于等于0遵循现有业务规则表示不限额。
- 已注册数只统计本系统已有非空 Emby ID 绑定的账号。Web 空档案和待开通资格不算已注册；已绑定但停用或到期的账号仍占现有注册席位。Emby 原生独立管理 owner 不属于系统注册池，不作为 Web 用户数混入。
- 预留和已占用直接复用 `Store.embyOccupancyLocked`：待开通资格、有效主影视注册码/白名单码、有效订单预留，以及开启自由开通时已有的潜在资格，保持与现有注册校验一致。独立分区卡、纯续期卡、过期卡不混入主影视注册池。
- 剩余可注册数为 `max(0, 总额 - 已占用)`，不是简单用总额减 Web 用户数；预留单列，避免有卡码预占时误报可用名额。不限额返回 `remaining: null` 并显示“不限”。
- 这是同一 Store 读锁下的只读汇总，既不签发卡码，也不占用或释放席位，不改动已有额度、订单、权限和开通校验。

新增可选摘要字段为 `registration: {limit, unlimited, registered, reserved, occupied, remaining}`，仅对未绑定 Emby 的当前认证用户返回；不接受查询参数指定的目标身份，不含任何会员明细。

## 验证

数据库回归验证 Web 档案不算已注册，绑定/停用/待开通/订单/主码/分区卡的统计与原占用校验一致，满额和不限额正确；接口与 Bot 验证未开通可见、已开通各类别不可见、无 Web 身份回退；原观影事实仍与 Mini App 一致。

Firefox 在360、768、1280宽度覆盖席位卡、注册后隐藏、满额/不限额、头部身份回退、签到积分更新、真实观影空状态及无横向溢出。隔离样例不写入生产，不能作为真实用户观影或注册数量。
